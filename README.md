# Token Lifecycle Lab

Интерактивная учебная CLI-утилита на Go для изучения жизненного цикла токенов.

Проект последовательно показывает, как token:

```text
выпускается → доставляется → хранится → передаётся → проверяется
→ обновляется/ротируется → истекает или отзывается
```

`v0.1` работает только с демонстрационной моделью в памяти.  
Никаких реальных токенов, браузера, сети, базы данных или внешних сервисов.

## Цель проекта

- Понять жизненный цикл access token, refresh token, JWT, API key и browser session.
- Изучить Go на небольшом завершённом CLI-проекте.
- Позже добавить JWT inspector, Web UI на чистом JavaScript и наблюдение за токенами в браузере.

## Текущая версия - `v0.1 — CLI Lifecycle Demo`

Пользователь нажимает `Enter`, а утилита переходит по стадиям и объясняет:

- что сейчас происходит с token;
- где он находится;
- может ли клиент использовать его;
- что проверит API;
- какое действие будет следующим.

## Восемь стадий

|   № | Стадия                   | Краткое описание                                            |
| --: | ------------------------ | ----------------------------------------------------------- |
|   1 | Выпуск                   | Сервер создаёт token, назначает TTL, claims и scopes        |
|   2 | Доставка                 | Token передаётся клиенту                                    |
|   3 | Хранение                 | Клиент сохраняет token в памяти, cookie или browser storage |
|   4 | Передача                 | Клиент отправляет token в API                               |
|   5 | Проверка и использование | API проверяет token и выполняет запрос                      |
|   6 | Обновление и ротация     | Выпускается новый token, старый может завершаться           |
|   7 | Истечение                | Token становится недействительным по TTL                    |
|   8 | Отзыв                    | Token досрочно запрещается сервером                         |

## Границы проекта

- Утилита не хранит и не отправляет реальные token values.
- Утилита не является Identity Provider, API Gateway или production auth-сервисом.
- Реальный статус отзыва JWT нельзя определить только по самому JWT: для этого нужен issuer, introspection endpoint или deny-list.
- На старте это учебная локальная лаборатория, а не средство управления production credentials.
